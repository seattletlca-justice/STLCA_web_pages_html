Methodology

How to check this work

Nothing here asks to be taken on trust. This page describes how the record universe is defined, what is verified and how, where the joins are, what the known limitations are, and what sets the ceiling on any claim published on this site.

The R.A.R.E. review model

01

Collect

Define the record universe and preserve the source.

02

Verify

Test completeness, dates, relationships, conflicts and gaps.

03

Trace

Connect findings back to supporting records and preserve provenance.

04

Publish what the evidence establishes — and what it does not.

R.A.R.E. does not decide what the records should say. It makes it possible to examine what they do say.

The source of truth

All landlord-tenant figures on this site derive from one frozen analytic CSV. Its SHA-256 is recorded in the data layer, declared independently by each of the seven district extracts, and checked at every build. If the file changes, the build fails rather than publishing a figure whose provenance no longer holds.

Known limitations

Inspection-date limitation — reproduced verbatim wherever an inspection-date figure appears
  • Missing data is not proof of non-occurrence. A blank inspection field does not prove no inspection occurred. A closed status does not by itself prove correction. A report not located in the searched public record is not proof it never existed elsewhere.
  • No complaint-to-violation linkage. The source record does not link a complaint to a resulting violation, so no conversion rate is computable. Ratios of record counts are labelled as such.
  • Address joins err in both directions. The RRIO feature matches two record systems on address. Certified properties whose address differs across systems will not match, and a matched address may cover different units or years.
  • Date fields are not internally consistent on every record. Negative recorded intervals — a close date preceding an open date — are present. Where a district page shows a timing figure, this is stated on that page.
  • Overlapping classification categories. A record can match more than one condition category, so category counts sum to more than the distinct records they describe.

The claim ceiling

Documented fact, reported statement, calculation, analysis, inference, allegation, finding and limitation stay visibly separate. A hedge travels with its claim: where a figure needs a qualifier, the qualifier appears with the figure, not in a footnote several screens down. Rewriting a claim does not strengthen the evidence behind it.

Failed QA does not publish. If a dataset, figure, page or evidence package fails QA, it is marked QA FAILED, NOT READY and is not presented as authoritative or public-ready until repaired and re-checked.

Reproducing this yourself

The site is static HTML, CSS and JavaScript with no build framework. From the STLCA_SITE/ directory: 

python build.py        # regenerate the data layer and district pages
python -m http.server 8000

The binding test: change a value in data/District_3_SUMMARY.json, run build.py, reload District 3, and the page reflects the change with no HTML edit. If that is not true, the binding is not real.
